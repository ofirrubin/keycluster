# Keycluster

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Python 3.11+](https://img.shields.io/badge/Python-3.11%2B-blue.svg)](https://www.python.org/)
[![Keycloak 26](https://img.shields.io/badge/Keycloak-26-orange.svg)](https://www.keycloak.org/)

Multi-tenant Keycloak on Kubernetes with per-realm domain isolation, dynamic
theming, and a management API.

## Overview

Keycluster automates the operational overhead of running Keycloak for multiple
tenants. Each tenant gets its own realm, custom domain, security policy, and
theme -- all managed through a single REST API.

Key capabilities:

- **Domain isolation** -- bind a public domain to a specific Keycloak realm and
  block cross-realm access at the Ingress level.
- **Security header management** -- configure CSP, HSTS, and X-Frame-Options
  per realm through the API instead of editing Keycloak admin settings by hand.
- **Dynamic theming** -- three bundled theme variants (`dynamic-standard`,
  `dynamic-half`, `dynamic-clean`) that load their configuration from the API
  at runtime, with dark/light mode and i18n support.
- **Role templates** -- define reusable sets of realm roles and apply them to
  any realm in one call.
- **Service accounts** -- create, list, delete, and rotate secrets for
  Keycloak service-account clients from a single endpoint.
- **Cluster health** -- aggregated health checks for Keycloak and the database.
- **Orphan cleanup** -- background job that removes Ingress resources and realms
  that are no longer mapped.

## Architecture

```
                         Internet
                            |
                      +-----+-----+
                      | Nginx     |
                      | Ingress   |
                      | Controller|
                      +-----+-----+
                            |
              +-------------+-------------+
              |                           |
    +---------+---------+       +---------+---------+
    |    Keycloak       |       |  Domain Manager   |
    | (custom image     |       |  (FastAPI, Python) |
    |  with themes)     |       |                   |
    +--------+----------+       +--------+----------+
             |                           |
             +----------+  +-------------+
                        |  |
                   +----+--+----+
                   | PostgreSQL |
                   +------------+
```

**Keycloak** -- Identity provider running a custom Docker image that bundles
the dynamic themes. Serves login, account, and admin pages.

**Domain Manager** -- FastAPI service that creates and updates Kubernetes
Ingress resources, patches Keycloak realm security headers, stores domain
mappings in PostgreSQL, serves theme configuration JSON, and manages role
templates and service accounts.

**PostgreSQL** -- Shared database for both Keycloak and Domain Manager tables.

**Nginx Ingress Controller** -- Routes external traffic to the correct backend
based on hostname and path rules generated by the Domain Manager.

## Prerequisites

- Kubernetes cluster (Minikube, Kind, EKS, GKE, or bare metal)
- `kubectl` configured with cluster access
- `docker` for building images
- Nginx Ingress Controller installed in the cluster

## Quickstart (Local / Minikube)

```bash
# 1. Start Minikube and enable Ingress
minikube start
minikube addons enable ingress

# 2. Point shell to Minikube Docker and build images
eval $(minikube docker-env)
docker build -t keycloak-custom:latest .
docker build -t domain-manager:latest ./services/domain-manager

# 3. Create secrets (edit k8s/secrets.yaml first!)
kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/secrets.yaml

# 4. Deploy database, then services
make deploy-db
kubectl wait --for=condition=ready pod -l app=postgres -n keycloak --timeout=60s
make deploy-all
kubectl wait --for=condition=ready pod -l app=keycloak -n keycloak --timeout=120s

# 5. Port-forward the Domain Manager
kubectl port-forward svc/domain-manager 8000:80 -n keycloak

# 6. Create a domain mapping
curl -X POST http://localhost:8000/domains \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin-token>" \
  -d '{
    "realm": "tenant-a",
    "domain": "auth.tenant-a.example.com",
    "ssl_required": "external",
    "hsts_max_age": 31536000
  }'
```

See [WALKTHROUGH.md](WALKTHROUGH.md) for a detailed step-by-step testing guide
and [INSTALLATION.md](INSTALLATION.md) for production deployment instructions.

## Configuration

### Domain Manager Environment Variables

| Variable | Required | Default | Description |
|:---|:---:|:---|:---|
| `DATABASE_URL` | Yes | -- | Async PostgreSQL connection string (`postgresql+asyncpg://...`) |
| `KEYCLOAK_SERVER_URL` | No | `http://keycloak:8080` | Internal URL of the Keycloak service |
| `KEYCLOAK_REALM` | No | `master` | Realm used for JWT verification of API callers |
| `KEYCLOAK_CLIENT_ID` | No | (empty) | OIDC client ID for audience validation; leave empty to skip |
| `KEYCLOAK_ADMIN` | Yes | -- | Username for Keycloak Admin API calls |
| `KEYCLOAK_ADMIN_PASSWORD` | Yes | -- | Password for Keycloak Admin API calls |
| `ADMIN_ROLES` | No | `admin,keycluster-admin,realm-admin` | Comma-separated realm roles that grant admin access |
| `CORS_ALLOWED_ORIGIN` | No | `*` | Allowed CORS origin; restrict in production |

A complete `.env.example` is available at `services/domain-manager/.env.example`.

### Keycloak Environment Variables

Standard Keycloak configuration applies. The notable settings used by
Keycluster are:

| Variable | Value | Notes |
|:---|:---|:---|
| `KC_DB` | `postgres` | Database vendor |
| `KC_HOSTNAME_STRICT` | `false` | Required for multi-domain support |
| `KC_PROXY_HEADERS` | `xforwarded` | Correct client detection behind Ingress |
| `KC_HEALTH_ENABLED` | `true` | Enables `/health` endpoint |
| `KC_METRICS_ENABLED` | `true` | Enables `/metrics` endpoint |

## API Reference

All mutating endpoints require a valid Bearer token with an admin role.

### Domains

| Method | Path | Auth | Description |
|:---|:---|:---:|:---|
| `POST` | `/domains` | Admin | Create or update a domain mapping and Ingress |
| `DELETE` | `/domains/{realm}` | Admin | Remove domain mapping and Ingress |
| `GET` | `/v1/domains/{realm}/health` | Admin | Health check for a mapped domain |
| `POST` | `/v1/domains/bulk` | Admin | Bulk create/update domain mappings |
| `POST` | `/cleanup` | Admin | Trigger background orphan cleanup |

### Themes

| Method | Path | Auth | Description |
|:---|:---|:---:|:---|
| `GET` | `/v1/themes/{realm}` | Public | Fetch theme config (used by login page JS) |
| `POST` | `/v1/themes/{realm}` | Admin | Save or update theme configuration |
| `DELETE` | `/v1/themes/{realm}` | Admin | Delete custom theme, reset to defaults |

### Role Templates

| Method | Path | Auth | Description |
|:---|:---|:---:|:---|
| `GET` | `/v1/role-templates` | Public | List all role templates |
| `POST` | `/v1/role-templates` | Admin | Create a role template |
| `PUT` | `/v1/role-templates/{id}` | Admin | Update a role template |
| `DELETE` | `/v1/role-templates/{id}` | Admin | Delete a role template |
| `POST` | `/v1/role-templates/{id}/apply/{realm}` | Admin | Apply template roles to a realm |

### Service Accounts

| Method | Path | Auth | Description |
|:---|:---|:---:|:---|
| `GET` | `/v1/realms/{realm}/service-accounts` | Admin | List service accounts in a realm |
| `POST` | `/v1/realms/{realm}/service-accounts` | Admin | Create a service account |
| `DELETE` | `/v1/realms/{realm}/service-accounts/{client_id}` | Admin | Delete a service account |
| `POST` | `/v1/realms/{realm}/service-accounts/{client_id}/rotate` | Admin | Rotate client secret |

### Cluster

| Method | Path | Auth | Description |
|:---|:---|:---:|:---|
| `GET` | `/v1/cluster/health` | Public | Aggregated cluster health status |
| `GET` | `/v1/cluster/metrics` | Admin | Basic cluster metrics |

### General

| Method | Path | Auth | Description |
|:---|:---|:---:|:---|
| `GET` | `/health` | Public | Domain Manager health check |

Interactive API documentation is available at `/docs` (Swagger UI) and
`/redoc` (ReDoc) when the Domain Manager is running.

## Themes

Three dynamic theme variants are included:

- `dynamic-standard` -- full-width login form with background image support.
- `dynamic-half` -- split layout with branding on one side.
- `dynamic-clean` -- minimal, centered card design.

All themes load their configuration at runtime from the
`GET /v1/themes/{realm}` endpoint. Customizable properties include primary,
secondary, and background colors, logo URL, font family, dark/light mode,
footer text, custom CSS, and login text overrides.

Set a realm's login theme to any of these names in the Keycloak Admin Console
to activate it.

## Security

See [SECURITY.md](SECURITY.md) for details on Ingress isolation, hostname
configuration, SSL/TLS setup, and theme integration security.

Key hardening steps for production:

- Set `ssl_required` to `all` or `external` on all domain mappings.
- Enable HSTS with a long `hsts_max_age` (recommended: 31536000).
- Restrict `csp_allowed_origins` to only trusted domains.
- Apply the network policy: `kubectl apply -f k8s/templates/network-policy-default.yaml`
- Use a secrets manager (Vault, AWS Secrets Manager) instead of plain
  `k8s/secrets.yaml` in production.
- Restrict `CORS_ALLOWED_ORIGIN` to your admin panel's origin.

## Troubleshooting

**Pods stuck in CrashLoopBackOff**

Check logs for the failing pod:
```bash
kubectl logs -l app=keycloak -n keycloak --tail=50
kubectl logs -l app=domain-manager -n keycloak --tail=50
```

Common causes: missing or incorrect `DATABASE_URL`, Keycloak cannot reach
PostgreSQL, secrets not applied.

**Domain mapping returns 404**

Verify the Ingress was created:
```bash
kubectl get ingress -n keycloak
```
Ensure DNS or `/etc/hosts` points the domain to the Ingress controller's IP.

**Cross-realm access not blocked**

Confirm the Ingress paths only allow `/realms/{realm}` for the bound domain.
Check that `use-regex` annotation is set to `"true"` on the Ingress.

**Keycloak redirects to wrong URL**

Ensure `KC_PROXY_HEADERS=xforwarded` is set in the Keycloak deployment and
`KC_HOSTNAME_STRICT=false` is enabled.

**Theme not loading custom config**

Verify the Domain Manager is reachable from the browser at
`/v1/themes/{realm}`. Check the browser console for CORS or network errors.
